O código implementa um sistema de **envelope digital**, um esquema de criptografia híbrida que combina a eficiência da criptografia simétrica com a criptografia assimétrica. Nesse sistema, o algoritmo **AES-GCM** é utilizado para cifrar a mensagem, enquanto o **RSA com OAEP** é utilizado para proteger a chave simétrica gerada especificamente para aquela mensagem. Dessa forma, o RSA não é utilizado para cifrar diretamente o conteúdo completo, mas somente a chave AES, permitindo o tratamento eficiente de mensagens de diferentes tamanhos.

A função `gerador_chaves_rsa` é responsável pela geração do par de chaves RSA utilizado pelo destinatário. Ela utiliza `rsa.generate_private_key` para gerar a chave privada, definindo o expoente público `65537` e o tamanho da chave por meio do parâmetro `tamanho_bits`. O valor padrão definido pela função é **2048 bits**, embora o programa também utilize uma chave de **3072 bits** no segundo teste. Depois da geração da chave privada, a função `privada.public_key()` obtém a chave pública correspondente. Ao final, são retornadas a chave privada e a chave pública, sendo que a chave pública pode ser utilizada pelo emissor para cifrar a chave AES, enquanto a chave privada correspondente é utilizada posteriormente pelo destinatário para recuperá-la.

A criação do envelope digital é realizada pela função `criar_envelope_digital`. Primeiramente, o programa gera uma chave simétrica aleatória de **256 bits** por meio de `AESGCM.generate_key(bit_length=256)`. Essa chave é utilizada para criar uma instância do algoritmo AES-GCM. Em seguida, o programa gera um `nonce` de **12 bytes** utilizando `os.urandom(12)`. Esse valor é utilizado pelo AES-GCM durante o processo de cifragem.

Com a chave AES e o `nonce` definidos, a mensagem original é cifrada pela chamada `aesgcm.encrypt(nonce, mensagem, associated_data=None)`. O AES-GCM, além de realizar a confidencialidade da mensagem, produz uma **tag de autenticação**, permitindo que o processo de descriptografia também verifique a integridade e a autenticidade dos dados cifrados. No código apresentado, não são utilizados dados associados adicionais, pois o parâmetro `associated_data` é definido como `None`.

Depois de cifrar a mensagem, o programa configura o esquema de preenchimento **OAEP (Optimal Asymmetric Encryption Padding)** para o RSA. A configuração utiliza `MGF1` com **SHA-256**, o próprio **SHA-256** como algoritmo de hash do OAEP e `label=None`. Essa mesma configuração será necessária posteriormente no processo de descriptografia.

A chave AES é então cifrada utilizando a chave pública RSA por meio de `chave_publica_rsa.encrypt(chave_simetrica_aes, padding_rsa)`. Nesse ponto está a principal característica do envelope digital: o conteúdo da mensagem é protegido pelo AES-GCM, enquanto a chave necessária para recuperar esse conteúdo é protegida pelo RSA-OAEP. Como o RSA é aplicado somente sobre a pequena chave AES, evita-se a necessidade de utilizar RSA diretamente sobre mensagens grandes.

Após esses procedimentos, o programa organiza os elementos necessários para a recuperação da mensagem em um dicionário chamado `envelope`. Ele contém três componentes: `chave_aes_cifrada`, que corresponde à chave AES protegida pelo RSA; `nonce`, necessário para a operação do AES-GCM; e `mensagem_cifrada`, que contém os dados cifrados juntamente com a informação de autenticação produzida pelo AES-GCM. Esse dicionário é então retornado pela função para representar o envelope digital.

A abertura do envelope é realizada pela função `decifrar_envelope_digital`, que executa o processo inverso. Inicialmente, o programa recria a configuração do padding OAEP utilizando novamente `MGF1` com SHA-256, SHA-256 como algoritmo principal e `label=None`. A utilização dos mesmos parâmetros empregados na cifragem é necessária para que a chave AES possa ser recuperada corretamente.

Em seguida, a função `chave_privada_rsa.decrypt` utiliza a chave privada RSA para descriptografar o campo `chave_aes_cifrada` armazenado no envelope. Se for utilizada uma chave privada que não corresponde à chave pública utilizada na criação daquele envelope, a operação de descriptografia RSA-OAEP falha e uma exceção é gerada. Dessa maneira, somente a chave privada correspondente consegue recuperar corretamente a chave AES utilizada na cifragem da mensagem.

Depois que a chave AES original é recuperada, o programa cria novamente uma instância de `AESGCM` utilizando essa chave. A função `aesgcm.decrypt` recebe o `nonce` armazenado no envelope e a `mensagem_cifrada`. Durante esse processo, o AES-GCM verifica a tag de autenticação associada ao texto cifrado. Se os dados tiverem sido alterados ou a chave AES estiver incorreta, a validação não será concluída com sucesso. Quando a operação é válida, a mensagem original é recuperada em bytes e retornada pela função.

Por fim, o programa realiza **três testes práticos** para demonstrar o funcionamento do esquema. No primeiro teste, é gerado um par de chaves RSA de **2048 bits**, uma mensagem curta é cifrada utilizando o envelope digital e, posteriormente, é descriptografada com a chave privada correspondente. O programa exibe a mensagem original, parte da chave AES cifrada, a mensagem cifrada e a mensagem recuperada, além de verificar se as mensagens original e descriptografada são iguais.

No segundo teste, é gerado um novo par de chaves RSA de **3072 bits** e é criada uma mensagem significativamente maior. O conteúdo é repetido 50 vezes justamente para demonstrar que o envelope utiliza o AES para proteger a mensagem, enquanto o RSA continua sendo utilizado apenas para proteger a chave AES. O programa compara o tamanho da mensagem original com o tamanho da mensagem cifrada e verifica se a mensagem longa foi recuperada corretamente após a descriptografia.

O terceiro teste verifica o comportamento do sistema diante de uma tentativa de descriptografia com uma chave privada incorreta. O envelope criado no primeiro teste, que foi protegido com a chave pública correspondente a `priv_1`, é submetido à função `decifrar_envelope_digital` utilizando `priv_2`. Como essa chave privada não corresponde à chave pública utilizada para proteger a chave AES, a operação falha e a exceção é capturada pelo bloco `try/except`. O programa então informa que ocorreu a falha esperada ao utilizar uma chave privada incorreta.

Portanto, o programa demonstra na prática o funcionamento de um **envelope digital baseado em criptografia híbrida**: o AES-GCM fornece a cifragem eficiente da mensagem e a verificação de integridade e autenticidade dos dados cifrados, enquanto o RSA-OAEP protege a chave AES e restringe sua recuperação ao detentor da chave privada correspondente. Os três testes demonstram, respectivamente, o funcionamento com uma mensagem curta, o tratamento de uma mensagem maior e a rejeição de uma tentativa de abertura utilizando uma chave privada incorreta.
